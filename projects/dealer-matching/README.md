# 딜러 매칭 플랫폼

홀덤펍 딜러 매칭 플랫폼 MVP. 사업계획서 v1.1의 MVP 범위를 동작하는 웹앱으로 옮긴 것.

## 실행

```bash
npm install
npm run db:push      # SQLite 생성
npm run db:seed      # 데모 데이터
npm run dev          # http://localhost:3000
```

첫 화면에서 데모 계정을 고르면 바로 로그인된다.

| 계정 | 역할 | 볼 것 |
|---|---|---|
| 강남 홀덤 라운지 | 가게 (구독 중) | 급구 공고에 지원자 3명 → 확정, 함께 일한 딜러 다시 부르기 |
| 더 리버 홀덤 · 홍대 카드룸 | 가게 (비구독) | 크레딧 차감 게재, 미출근 신고 소명 기록 |
| 지원 J | 딜러 (프로) | 공고 리스트·가게 별점, 원탭 지원, 제안 카드 수락, 월 수입 |
| 민수 M | 딜러 | 프로필에 "미출근 신고 1건 · 소명 있음" 표시 |

`npm run db:studio` 로 Prisma Studio를 열면 관리자 작업(신고 인정, 제재)을 테이블에서 직접 한다. MVP에는 관리자 화면이 없다.

## 구현된 흐름

- 역할 선택 온보딩 (딜러/가게). 딜러만 생년월일로 만 18세 판정, 가게는 휴대폰·가게명·위치만
- 숨고 스타일 디자인 (흰 바탕 · 블루 강조 · Pretendard). 밝은 화면 기본, 첫 화면과 MY의 토글로 어두운 화면. 쿠키에 저장
- 딜러 요청(공고) 등록: 일시·인원·시급·경력·성별·나이대(선호, `PREF_FIELDS` 플래그)·추가사항. 게임 항목 없음. 구독 무료 / 비구독 크레딧 차감
- 딜러 홈 = 숨고의 "받은 요청 / 보낸 견적". 오늘·내일·급구·지역 필터, 24시간 내 요청 자동 급구 표시
- 견적 보내기: 딜러가 희망 시급 + 한마디를 보냄. 수정·철회 가능
- 가게는 받은 견적을 비교(시급, 메시지, 후기, 노쇼, 우리 가게 근무 이력)해 하나를 확정. 확정 시급은 견적 시급 (트랜잭션: 매치 생성, 나머지 견적 마감, 요청 상태 변경)
- 채팅 + 근무 제안 카드 (조건 변경·재고용용), 수락 즉시 확정
- 원탭 재고용 (근무 이력 있는 딜러에게 날짜·시간만 골라 제안)
- 근무 완료 처리 → 정산서 (시급 × 시간, 3.3% 안내)
- 확정 취소 (근무 6시간 이내면 늦은 취소 카운트)
- 미출근 신고 → 24시간 소명 → 소명 없으면 자동 노쇼 확정, 있으면 양쪽 진술을 가게에 표시 (판정하지 않음)
- 비대칭 평가: 딜러→가게 별점은 딜러만, 3건 이상일 때만 노출. 가게→딜러 후기는 가게만. 자유 텍스트 없음, 태그만
- 신고 접수, 가게 신고 누적 제재 단계 (`acceptStoreReport`)

## 실서비스 연결 지점

한 파일씩 교체하면 된다.

| 무엇 | 지금 | 교체 |
|---|---|---|
| 로그인 | 쿠키에 userId (`lib/session.ts`) | 카카오/네이버 OAuth + PASS 본인인증 |
| DB | SQLite (`prisma/schema.prisma`) | `provider = "postgresql"` 로 바꾸고 Supabase URL |
| 결제 | 구독 토글, 크레딧 숫자 (`toggleSubscription`) | 토스페이먼츠 빌링키 + 웹훅 |
| 알림 | 없음 | 카카오 알림톡 (지원·확정·리마인드 시점은 `lib/actions.ts` 각 액션 끝) |
| cron | 페이지 진입 시 `settleNoShows()` | Vercel Cron |
| 관리자 | Prisma Studio | 2차 관리자 화면 |

운영 상수(연령, 게재비, 구독료, 취소 페널티 시간, 소명 기한, 제재 단계)는 전부 `lib/const.ts` 에 있다.
