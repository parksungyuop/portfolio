# 계획서: 컴퓨터 소리 무시 (Echo Guard)

작성 2026-09-30

## 목표
컴퓨터 스피커에서 나는 소리(음악·영상·게임)가 마이크로 되돌아와도 비서이 이를 사람 목소리·박수·호출어로 오인하지 않게 한다.

## 현재 문제
- 마이크의 에코 제거(Chromium)는 비서 자신의 목소리만 지운다. Spotify 등 다른 앱 소리는 그대로 들어온다.
- 영향: ① 듣는 중 노래가 같이 받아 적힘, 노래 때문에 "말 끝"을 못 찾음 ② 항상 듣기에서 가사가 명령으로 들어감 ③ 드럼 비트가 박수로 오인될 수 있음.

## 방법
1. **기준 신호**: 렌더러가 시스템 출력(루프백)을 받아 크기(RMS)만 main 으로 보낸다. 소리 내용은 보내지 않는다.
2. **판정(EchoGuard)**: 최근 0.4초의 출력 크기 평균과 마이크 크기 평균의 비율로 "컴퓨터 소리만 날 때의 결합 비율"을 추정한다(최솟값 추적, 천천히 상승). 지금 마이크 크기가 `출력 × 결합비율 × 2.5` 보다 작으면 컴퓨터 소리뿐이라고 본다.
3. **적용**
   - 음성 인식·호출어: 컴퓨터 소리뿐인 조각은 무음으로 바꿔 넣는다.
   - 박수: 컴퓨터 소리뿐인 조각은 검출기에 넣지 않는다.
4. **끄는 손잡이**: `voice.echoGuard` (기본 켜짐).

## 비판 검증
| 우려 | 판단 |
|---|---|
| 음악보다 작게 말하면 목소리도 버려진다 | 맞다. 한계로 명시. 여유 2.5배(8dB)로 시작하고 로그로 조정 |
| 헤드폰이면 마이크에 소리가 안 들어와 결합 비율이 0에 가까워진다 | 비율이 작아질 뿐 목소리는 항상 통과. 문제없음 |
| 루프백과 마이크의 시간차 | 0.4초 평균으로 흡수 |
| 음량을 바꾸면 결합 비율이 달라진다 | 내려갈 땐 즉시, 올라갈 땐 초당 약 20% 추적. 몇 초 안에 적응 |
| 화면 캡처 권한·부하 | 영상 트랙은 받자마자 중지, 소리 크기만 사용 |
| 완전한 에코 제거(AEC)가 아니다 | 목소리와 음악이 겹친 구간은 음악이 섞여 Whisper 로 간다. 필요하면 다음 단계로 "듣는 동안 음량 낮추기" 추가 |

## 검증
- 단위 테스트: 음악만 → 에코 판정, 음악+목소리 → 통과, 출력 없음 → 통과.
- 실기: 음악 재생 중 로그에 `echo` 비율이 찍히고, 박수·호출 오작동이 없는지 확인.

## 실측 뒤 변경 (2026-09-30)
- **크기 비교 방식 폐기**: 음악만 나는 구간에서 조각의 2~48%만 "컴퓨터 소리"로 판정됐다. 마이크의 자동 음량·잡음 억제 때문에 마이크/출력 비율이 0.05~0.25로 출렁인다.
- **박수 거르기 폐기**: 조각을 건너뛰면 검출기가 음악 크기를 배우지 못해 오히려 오작동(거짓 호출 1회)했다. 기존 검출기는 음악 9분 동안 거짓 호출 0회였다.
- **확정 방식**
  1. 듣는 동안(듣기·이어 말하기·받아쓰기) 컴퓨터 소리가 나고 있으면 시스템 음소거, 끝나면 해제. 비서이 말할 때는 해제된 상태다.
  2. 항상 듣기 모드에서는 컴퓨터 소리가 나는 동안 들린 말을 버린다. 박수·호출어·단축키·입력칸으로 부르면 정상 동작.
  3. 루프백은 "지금 컴퓨터에서 소리가 나는가"만 판단하는 데 쓴다.
- **남는 한계**: 음소거 전환에 약 1초 걸린다. 호출 직후 1초는 음악이 섞일 수 있다.
