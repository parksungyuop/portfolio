# 모듈 구성안 — 토큰 절약 · 자연스러운 대화 · 학습/보관 점검

작성: 2026-10-26 · 대상: dmbot (Cloudflare Worker + Supabase + Claude Haiku 5.5)

## 0. 지금 상태 (실측)

### 답장 1건이 Claude에 보내는 양
`count_tokens`(무료)로 실제 프롬프트 틀에 중앙값 크기의 말투 프로필을 넣어 쟀다. 오차는 ±15% 정도.

| 구성 | 토큰 |
|---|---|
| 고정 규칙 (일반 상대) | 약 3,000 |
| 말투 지침 + 실제 대화 예시 (중앙값 프로필) | 약 3,000 (가장 큰 프로필은 약 5,500) |
| 오늘·상황·캘린더 + 최근 대화 20줄 | 약 800 |
| **합계: 일반 상대** | **약 6,800** |

### 비용
- Haiku 5.5 요금은 입력 $0.10, 출력 $0.50 (100만 토큰당)이다.
- 답장 1건은 입력 약 $0.0007에 출력(JSON과 생각)을 더해 **약 1원**이 든다.
- 지난 7일 동안 받은 메시지는 하루 약 90통이다. 묶기와 짧은 맞장구를 빼면 Claude 호출은 하루 약 60회로 추정한다.
- 그래서 지금은 **한 달 약 2천 원** 수준이다.
- 따라서 이 계획으로 얻는 건 절약액 자체보다 다음 세 가지다.
  - **속도**: 입력이 줄면 응답이 빨라진다.
  - **품질**: 상관없는 규칙이 적을수록 AI가 지시를 더 잘 지킨다.
  - **사람이 늘어날 때 대비**.

### 지금 구조의 낭비
1. **같은 고정 규칙 3,000토큰을 매번 처음부터 읽힌다.**
   - 캐시 표시(`cache_control`)가 없다.
   - 상대마다 다른 말투 지침이 **고정 규칙보다 앞에** 있어서, 캐시를 켜도 상대끼리 앞부분을 공유하지 못한다.
2. **이번 메시지와 상관없는 규칙도 매번 다 들어간다.**
   - 예: 약속 규칙 약 700토큰, 스토리 규칙, 호출 규칙. 대부분의 메시지는 약속 얘기가 아니다.
3. **최근 대화는 무조건 20줄이다.** 어제 끝난 얘기까지 매번 들어간다.
4. **사용량 기록이 없다.** 응답의 `usage`를 저장하지 않아서 실제로 얼마를 쓰는지, 절약이 됐는지 확인할 수 없다.

## 1. 전체 흐름 (제안)

```
인스타 웹훅
  │
  ▼
[M1 수신]  서명 확인 · 암호화 저장 · 큐 적재 · 연속 메시지 20초 묶기          ← 지금 있음
  │
  ▼
[M2 게이트]  전체/상대 자동발송 · 일시정지 · 24시간 창 · echo 판별             ← 지금 있음
  │
  ▼
[M3 코드 라우터]  Claude 없이 끝낼 수 있으면 여기서 끝냄                       ← 확장
  │   ├─ 템플릿 답장 (맞장구, 이름만 부름, 고백)
  │   ├─ 오너에게 넘김 (민감 키워드, 봇이냐는 질문)
  │   └─ 무시 (웃음·이모지만, 첨부만)
  ▼
[M4 문맥 조립]  최근 대화(적응형) + 기억 메모 + 오늘 상황/캘린더 + 필요한 규칙만  ← 신규
  │
  ▼
[M5 프롬프트 조립]  [고정 규칙 · 1시간 캐시] → [이 상대 블록 · 5분 캐시] → [이번 메시지]  ← 신규
  │
  ▼
Claude Haiku 5.5 (JSON 출력)
  │
  ▼
[M6 출력 검사]  메타 문구 · 금지 표현 · 웃음 제한 · 캘린더 충돌 · 반복 검사      ← 지금 있음 + 반복 검사
  │
  ▼
[M7 발송]  답장 타이밍(내 실제 답장 속도처럼) · 1회 발송 보장                   ← 타이밍 개선
  │
  ▼
[M8 기록·학습]  사용량 기록 · 기억 메모 저장 · 주 1회 말투 재학습               ← 신규
```

### 파이썬 vs 코드
"Claude에 가기 전에 코드로 최대한 처리"하는 부분은 전부 **Worker(JavaScript) 안에서** 한다.

- 메시지가 오는 순간 처리해야 해서 별도 파이썬 서버를 두면 왕복만 늘어난다.
- 같은 판단(정규식, 통계, 캘린더 계산)은 JS로도 똑같이 된다.

파이썬(`tools/analyze_tone.py`)은 지금처럼 **인스타 내보내기 파일로 말투를 처음부터 다시 만들 때만** 쓴다.

### 파일 배치
`bot.js`에 몰려 있는 걸 두 개로 나눈다. 나머지는 그대로 둔다.

| 파일 | 담당 |
|---|---|
| `worker/src/prompt.js` (신규) | M4 · M5: 문맥 조립, 규칙 블록, 캐시 배치 |
| `worker/src/learn.js` (신규) | M8: 사용량 기록, 기억 메모, 말투 재학습 |
| `worker/src/bot.js` | M2 · M3 · M6 · M7 (지금 코드 유지) |

## 2. 토큰 절약 (항목 1)

### 2-1. 프롬프트 순서를 바꾸고 캐시를 켠다 — 가장 큰 효과, 품질 변화 없음
Claude 캐시는 **앞부분이 글자 하나까지 같을 때만** 맞는다. 바뀌지 않는 것을 앞에, 자주 바뀌는 것을 뒤에 둔다.

```
system[0]  고정 규칙  — 모든 상대 공통, 글자 하나 안 바뀜         cache_control: 1시간
system[1]  이 상대 블록 — 말투 지침 · 예시 · 관계 정보 · 존댓말/반말 규칙   cache_control: 5분
messages   이번 메시지 — 오늘·상황·캘린더 · 이번에 필요한 규칙 · 최근 대화 · 요청   (캐시 안 함)
```

- **고정 규칙 안의 '상대마다 다른 부분'을 빼낸다.**
  - 존댓말/반말 판정, 수락 명단 여부는 '이 상대 블록'으로 옮긴다.
  - 웃음 비율(상대 메시지마다 바뀜)은 '이번 메시지'로 옮긴다.
- 내 말 뜻(용어 풀이)과 금지 표현은 고정 규칙에 둔다. 대시보드에서 고칠 때만 캐시가 한 번 새로 만들어지니 괜찮다.
- **Haiku 5.5 캐시 조건**
  - 최소 512토큰. 고정 규칙(약 3,000)과 상대 블록(약 3,000) 모두 넘는다.
  - 캐시 읽기는 **입력 요금의 10%**다.
  - 캐시 만들기는 5분짜리가 1.25배, 1시간짜리가 2배다.
- **효과**: 같은 사람과 주고받는 동안(5분 안)은 입력 약 6,000토큰이 90% 할인된다. 한 시간에 답장이 두세 번만 있어도 고정 규칙은 1시간 캐시가 이득이다.
- **주의**: 캐시가 빗나가면 그 부분은 오히려 1.25~2배다. 그래서 **2-5 사용량 기록을 먼저** 넣고, 실제 적중률(`cache_read_input_tokens`)을 보고 판단한다.

### 2-2. 상관없는 규칙은 넣지 않는다 (조건부 규칙)
코드가 이번 메시지를 먼저 훑고, 해당될 때만 그 규칙을 '이번 메시지' 칸에 붙인다. 고정 규칙에서는 빼서 앞부분은 계속 같게 유지한다.

| 규칙 묶음 | 넣는 조건 (코드 판정) | 약 토큰 |
|---|---|---|
| 약속 구분·캘린더 거절 | 날짜·요일·시각·`보자/만나/약속/언제/시간 돼` 등이 있거나, 최근 대화에 진행 중인 약속 얘기가 있을 때 | 700 |
| 스토리 답장 | 메시지에 "(내 스토리에 답장)" 표시가 있을 때 | 120 |
| 이름만 부름 | M3 라우터가 템플릿으로 처리 → Claude에 안 감 | 150 |
| 오랜만 연락 | 마지막 대화가 설정 일수 이상 지났을 때 (지금도 조건부) | 80 |

- 일반 상대는 평소 **약 800~1,000토큰이 줄어든다.**
- 판정이 애매하면 넣는 쪽으로 한다. 빠뜨려서 생기는 실수가 토큰보다 비싸다.

### 2-3. 고정 규칙 다듬기
같은 말이 여러 번 나오는 곳을 합친다.

- 예: "지금 위치는 상황판 우선"이 세 군데, "no_reply 하는 경우"가 두 군데 흩어져 있다.
- 지금 AI(Haiku 5.5)는 짧고 분명한 지시를 더 잘 따른다.
- 목표: 약 3,000 → **약 2,000토큰**.
- 바꾸기 전과 후를 아래 '확인 방법'의 샘플 메시지 묶음으로 비교한다.

### 2-4. 예시와 최근 대화의 양을 맞춘다

**실제 대화 예시**
- 지금은 프로필에 저장된 그대로 넣는다(중앙값 1,691자, 최대 4,531자).
- 재학습(4-3) 때 **대표 8쌍, 1,200자 이내**로 골라 저장한다.
- 메시지마다 고르면 캐시가 깨지므로 고르는 건 프로필을 갱신할 때 한 번만 한다.

**최근 대화**
- 20줄 고정을 버린다.
- **마지막 대화 흐름**(앞 메시지와 3시간 넘게 끊긴 곳부터)을 넣되, 최소 6줄, 최대 12줄로 한다.
- 그보다 오래된 내용은 **기억 메모**(3-3)가 맡는다.
- 줄어드는 양은 약 300~400토큰이다.

### 2-5. 사용량 기록 (먼저 할 것)
- Claude 응답의 `usage`(입력, 출력, 캐시 읽기, 캐시 만들기)를 종류별(답장, 요약, 재학습)로 하루 단위로 더해 `claude_usage` 표에 저장한다.
- 외부 호출 한도(실행당 45회)를 아끼려고 **실행 한 번에 한 번만** 저장한다.
- 대시보드 설정 탭에 "오늘 · 이번 달 토큰 / 예상 비용" 한 줄을 띄운다.

### 2-6. 출력 줄이기
- 출력 요금은 입력의 5배다.
- `note`(판단 메모)는 오너 확인용이라 필요하지만 **40자 이내 한 마디**로 제한한다(스키마 설명과 코드 자르기).
- 생각 정도(`effort: low`)는 지금 그대로 둔다.

### 2-7. 기다려도 되는 작업은 배치로 (나중에)
- 요약과 재학습은 바로 필요 없는 작업이라 **Message Batches(50% 할인, 캐시 할인과 겹침)** 대상이다.
- 지금 양(요약 하루 약 12건)으로는 절약이 하루 몇 원 수준이고, 결과를 다음 실행에서 가져오는 코드가 필요하다.
- **재학습 대상이 주 30명을 넘으면** 도입한다.

### 예상 효과 (일반 상대 1건)

| 단계 | 입력 토큰 (요금 기준 환산) |
|---|---|
| 지금 | 6,800 |
| 2-2 · 2-3 · 2-4 적용 | 약 4,900 |
| + 캐시 적중 (같은 대화 중) | 약 1,400 |
| + 캐시 빗나감 (첫 메시지) | 약 5,900 |
| **적중률 60% 가정 평균** | **약 3,200 (−50% 이상)** |

여기에 라우터 확장(3-1)으로 Claude 호출 자체가 10~20% 줄어든다고 추정한다. 사용량 기록으로 확인한다.

## 3. 자연스러운 대화 (항목 2)

### 3-1. 코드 라우터 확장 (M3)
Claude 없이 처리해서 토큰도 아끼고 말투도 일정하게 한다.

| 경우 | 처리 | 지금 |
|---|---|---|
| 짧은 맞장구 (ㅇㅋ, ㅇㅇ, 넵, ㅋㅋ만) | 그래 / ㅇㅋ / 넵 | 있음 |
| 이름만 부름 ("길동아", "야", "형", "저기") | 반말 상대: 왜? / 뭔일이야 / 무슨 일이니 중 무작위. 존댓말 상대: 네 무슨 일이세요? 남자로 적힌 반말 상대만 가끔 "무슨 일이십니까" | AI가 판단 → **코드로** |
| 돈·계좌·송금·빌려·인증번호·비밀번호 | Claude에 보내지 않고 바로 '확인 필요' | AI가 판단 → **코드로** |
| "봇이야?", "AI야?", "자동응답이야?" | 바로 '확인 필요' | AI가 판단 → **코드로** |
| 이모지·반응·첨부만 | 답하지 않음 | 확인 후 유지 |

### 3-2. 말투를 숫자로 알려 준다
"길이는 상대와 비슷하게" 같은 말 대신, 코드가 계산한 숫자를 '이번 메시지'에 한 줄로 넣는다. 지시가 짧아지고 더 정확해진다.

```
[이번 답장 목표] 길이 8~18자 · 이모지 0개 · 문장 1~2개 · 질문 최대 1개
```

- 길이: 이 상대에게 내가 보낸 실제 메시지 길이(재학습 통계)와 상대 최근 메시지 길이의 중간.
- 이모지와 웃음: 내 실제 사용 빈도.

### 3-3. 기억 메모 (상대가 말한 일정·취향 기억)
- 답장을 만드는 **같은 호출에서** JSON 스키마에 `remember` 칸을 추가한다.
  - 0~2개, 각 30자 이내. 예: "11/2 면접", "고양이 키움", "매운 거 못 먹음".
  - 추가 호출이 없고 출력은 약 20토큰 늘어난다.
- `contact_facts` 표에 **암호화**해서 저장한다.
  - 상대당 최근 10개까지 둔다.
  - 날짜가 있는 일정은 그 날짜 7일 뒤에 지운다.
- 프롬프트에는 `[기억] 11/2 면접 · 고양이 키움 · …`처럼 한 줄로 넣는다.
- 이렇게 하면 "오늘 면접 잘 봤어요?" 같은 꼬리질문이 실제로 작동한다. 지금은 최근 20줄 안에 있을 때만 된다.

### 3-4. 반복 방지 (M6)
- 보내기 직전, 이 상대에게 최근 보낸 봇 메시지 10개와 비교한다.
- **똑같은 문장**이나 **같은 시작말이 3번 연속**이면 다음과 같이 한다.
  - 같은 문장: 보내지 않고 '확인 필요'로 넘긴다.
  - 같은 시작말: 다음 프롬프트에 "최근 쓴 시작말: ○○, ○○ — 다르게 시작"을 한 줄 넣는다.

### 3-5. 답장 타이밍 (M7)
- 지금은 받은 뒤 20초를 기다린다. 연속 메시지는 묶이지만 매번 너무 빠르고 일정하다.
- 재학습 때 이 상대에게 **내가 실제로 답한 시간**(상대 메시지 → 내 메시지 간격의 중앙값)을 계산해 두고, 그 근처에서 무작위로 기다린다.
  - 예: 친한 친구 30초~2분, 그 외 1~4분.
- 상한은 대시보드에서 정한다(기본 3분).
- **인스타 '입력 중…' 표시**
  - 보내기 몇 초 전에 띄우면 더 자연스럽다.
  - 인스타 발송 API의 `sender_action: typing_on`이 지금 버전에서 되는지 **먼저 확인**해야 한다.
  - 외부 호출이 1회 늘어난다.

### 3-6. 대화 마무리
- 상대가 마무리 말(잘자, 굿밤, 나중에 연락할게)을 하면 짧게 받고 끝낸다. 이 규칙은 지금 일부 상대에게만 있다.
- 이 규칙을 **모든 상대**로 넓히고, 코드에서 같은 대화에 마무리 인사가 두 번 오가면 더 답하지 않는다.

### 4-1. 고칠 것: 주 1회 말투 재학습 (M8, `learn.js`)
매일 새벽 작업 안에서 **한 번에 몇 명씩** 처리한다(무료 플랜 실행 한도 때문).

1. **대상**
   - 마지막 갱신 뒤 **내가 보낸 메시지(`owner`)가 20개 이상** 쌓인 상대.
   - 프로필이 없는 상대는 30개가 넘으면 새로 만들고 연결한다.
2. **재료**
   - 그 상대와의 최근 대화에서 **내 메시지와 그 앞의 상대 메시지**를 쓴다.
   - **봇 메시지는 빼고**, 봇 답장 바로 뒤의 상대 반응도 뺀다.
3. **코드로 계산**(Claude 없음)
   - 존댓말 비율, 평균·중앙 길이, 이모지·웃음 빈도, 자주 쓰는 어미, 답장 속도.
   - 결과는 `stats`에 저장하고 3-2와 3-5의 숫자로 쓴다.
4. **Claude 1회**: 기존 말투 지침 + 위 통계 + 최근 내 메시지를 넣고, 다음 두 가지를 받는다.
   - **고친 말투 지침**(900자 이내).
   - **대표 대화 예시 8쌍**.
5. **안전장치**
   - 바로 전 지침은 `style_guide_prev`에 보관해 대시보드에서 [되돌리기]할 수 있게 한다.
   - 지침이 너무 짧거나 금지 표현이 들어가면 반영하지 않는다.

### 4-2. 요약을 기억으로 쓰기 + 암호화
- 요약을 `summary_enc`로 **암호화**한다. 대시보드는 지금 'history'처럼 API를 거쳐 받는다.
- 기억 메모(3-3)가 생기면 답장에는 기억 메모를 쓰고, 요약은 대시보드용으로 남긴다. 둘 다 넣으면 토큰이 겹친다.

### 4-3. 보관 정책
- 원문 메시지 90일 보관은 그대로 둔다(개인정보 최소 보관).
