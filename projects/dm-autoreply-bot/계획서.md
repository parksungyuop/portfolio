## 0. 핵심 결정 요약

| 항목 | 결정 | 이유 |
|---|---|---|
| Meta API | **Instagram API with Instagram Login** (`graph.instagram.com`) | 페이스북 페이지 연결 불필요, 공식 API |
| 서버 | PHP 8, **Composer 의존성 0개** (cURL·openssl·json 내장 확장만) | 공유 호스팅 제약 |
| 대기열·잠금 | Supabase Postgres 함수 `claim_jobs()` — `FOR UPDATE SKIP LOCKED` + 임대(lease) 만료 | 크론 중복 실행·타임아웃 모두를 DB 한 곳에서 해결 |
| 이중 발송 방지 | ① 크론 `flock` ② DB 임대 ③ `send_log.queue_id UNIQUE` ④ "발송 중" 상태 선기록 | 겹겹이 막되, 마지막 안전장치는 DB 제약 |
| 발송 보장 수준 | **최대 1회(at-most-once)** | 같은 DM 두 번 가는 것 > 한 번 누락이 더 나쁨. 애매한 건은 `needs_review`로 대시보드 표시 |
| 발송 경로 | **`ig_send()` 단일 함수만 Graph API 호출**, 호출 직전 매번 전체 스위치 DB 재조회 | "전체 OFF 시 어떤 경로로도 발송 금지"를 코드 한 곳에서 강제 |
| 답변 모델 | `claude-haiku-5-5` (답변·요약·말투 학습) | 비용 최소화 (답장 1건 약 $0.0004). 품질이 아쉬우면 답변만 `claude-sonnet-5-5` 로 |
| 암호화 | AES-256-GCM (`openssl_encrypt`), 키는 public_html 바깥 | 원문 암호화 요구사항 |
| 말투 분석 스크립트 | Python 3 표준 라이브러리만 (`urllib`, `json`) + 업로드 시 `cryptography` 1개 | 오너 PC 1회 실행 |
| 대시보드 | Vite + 순수 JS + `@supabase/supabase-js` → `dist/` 업로드 | 정적 빌드, 프레임워크 불필요 |

## 1. 전체 구조

```
[Instagram] ──webhook POST──▶ public_html/ig/webhook.php
                                 │ 서명검증 → queue INSERT → 200 즉시
                                 │ fastcgi_finish_request() 가능 시 → worker 1회 인라인 실행
                                 ▼
                          [Supabase: queue]
                                 ▲
cPanel cron (1분) ──▶ ~/dmbot/cron/worker.php ── claim_jobs() ──▶ 판단 ──▶ Claude ──▶ ig_send()
cPanel cron (일 1회) ─▶ ~/dmbot/cron/daily.php  (요약 · 토큰 갱신 · 로그 정리)

[대시보드 /ig/dash/] ──anon key + 로그인 JWT──▶ Supabase (RLS: 오너만)
                    └──JWT──▶ public_html/ig/api.php (복호화 필요한 조회, 수동 요약 갱신)

[오너 PC] analyze_tone.py ──service role──▶ Supabase (tone_profiles, contacts)
```

## 2. 데이터베이스 (Supabase)

| 테이블 | 주요 컬럼 | 비고 |
|---|---|---|
| `settings` (1행) | `global_enabled bool`, `pause_minutes int=30`, `trigger_phrases text[]`, `intro_message text`, `reply_delay_sec int=20` | 대시보드 수정 가능 |
| `contacts` | `igsid PK`, `username`, `name`, `auto_enabled bool`, `paused_until timestamptz`, `profile_id`, `last_user_msg_at`, `last_msg_at`, `summary`, `summary_at` | 상대 목록 |
| `tone_profiles` | `id`, `contact_key`(username), `is_default bool`, `stats jsonb`, `style_guide text`, `examples_enc text` | 기본 프로필 1개 + 상대별 |
| `messages` | `mid UNIQUE`, `igsid`, `direction`(in / bot / owner), `text_enc`, `ts` | 맥락용 원문 (암호화) |
| `queue` | `id`, `kind`(inbound / echo / intro), `mid UNIQUE`, `igsid`, `payload_enc`, `status`, `attempts`, `not_before`, `locked_until`, `last_error` | `mid UNIQUE` → 웹훅 재전송 중복 자동 무시 |
| `send_log` | `queue_id UNIQUE`, `igsid`, `text_enc`, `ig_mid`, `status`(sending / sent / failed / blocked_off / expired), `created_at` | 발송 이력·echo 판별 |

`queue.status`: `pending → processing → sending → done` / `expired`(24h 초과) / `skipped`(OFF·토글·일시정지) / `failed`(재시도 소진) / `needs_review`(발송 여부 불확실)

### RPC 함수
```sql
-- 처리할 작업을 원자적으로 가져감. 동시에 두 워커가 불러도 같은 행을 못 가져감.
claim_jobs(p_limit int, p_lease_sec int) returns setof queue
  -- WHERE status IN ('pending','processing') AND not_before <= now()
  --   AND (locked_until IS NULL OR locked_until < now())
  -- FOR UPDATE SKIP LOCKED → status='processing', locked_until=now()+lease, attempts+1
```

### RLS
- 모든 테이블 RLS ON. 정책: `auth.uid() = '<오너 UUID>'` 만 SELECT/UPDATE (대시보드가 쓰는 테이블·컬럼만).
- `queue`, `send_log`의 암호문 컬럼은 대시보드에서 직접 안 읽음 → 복호화가 필요한 화면은 `api.php` 경유.
- Supabase Auth: **신규 가입 비활성화**, 오너 계정 1개만 수동 생성.
- service role 키는 `config.php`와 오너 PC 스크립트에만 존재.

## 3. 단계별 구현

### 단계 1 — 말투 학습 스크립트 (`tools/analyze_tone.py`, 오너 PC)
1. 입력: "내 정보 다운로드"(JSON 형식) 압축 해제 폴더 → `your_instagram_activity/messages/inbox/*/message_*.json` 전체 탐색
2. 한글 복원: 모든 문자열에 `s.encode('latin-1').decode('utf-8')` (실패 시 원본 유지)
3. 최근 1년(`timestamp_ms`) 필터, 1:1 대화만 (단톡방은 기본 프로필 통계에만 사용)
4. 상대 식별: 폴더명(`username_숫자`) + `participants[].name`
   - ⚠️ **내보내기 파일에는 IGSID가 없다.** IGSID 매칭은 서버에서 처리: 새 상대 첫 메시지 시 `GET /{IGSID}?fields=username,name` 조회 → `tone_profiles.contact_key`(username)와 매칭. 실패 시 닉네임 매칭, 그래도 없으면 기본 프로필.
5. 상대별 통계(코드로 계산): 문장 끝 어미 Top 10, 이모지/ㅋㅋ/ㅎㅎ 빈도, 존댓말 비율(`요/습니다/세요` 종결 비율), 평균·중앙 길이, 메시지 쪼개 보내는 습관(연속 전송 수), 자주 쓰는 표현 n-gram
6. 상대별 `style_guide`: 통계 + 대표 대화 쌍 15개를 Claude에 넘겨 "말투 지침" 텍스트 생성 (오너 메시지 30개 미만 상대는 생략 → 기본 프로필 사용)
7. 기본 프로필: 전체 1:1 대화 기준 동일 처리
8. 업로드: `tone_profiles` upsert, `examples_enc`는 서버와 같은 키·형식(AES-256-GCM)으로 암호화
9. `--dry-run` 옵션: 업로드 없이 `profiles_preview.json`만 생성 → 오너가 먼저 확인

### 단계 2 — 웹훅 (`public_html/ig/webhook.php`)
- **GET**: `hub.mode=subscribe` & `hub.verify_token` 일치 → `hub.challenge` 그대로 출력, 아니면 403
- **POST**:
  1. `php://input` 원문으로 `hash_hmac('sha256', $raw, APP_SECRET)` ↔ `X-Hub-Signature-256` `hash_equals` 비교, 불일치 403
  2. `entry[].messaging[]` 순회 → 텍스트 메시지만 큐 적재 (`kind`=inbound 또는 echo, `mid` 기준 중복 무시). 리액션·읽음·삭제 이벤트는 무시
  3. 즉시 `200 EVENT_RECEIVED`
  4. `function_exists('fastcgi_finish_request')` → 응답 종료 후 `worker_run(시간예산 20초)` 인라인 실행 (크론과 같은 잠금 사용). 없으면 아무것도 안 함 → 크론이 처리
- 웹훅 구독 필드: `messages`, `message_echoes`

### 단계 3 — 워커 (`cron/worker.php`, 1분 주기)
```
flock(LOCK_EX | LOCK_NB) 실패 → 즉시 종료          // 1차 잠금
set_time_limit(55); 시간예산 45초, 1회 최대 10건
jobs = claim_jobs(10, lease=120초)                  // 2차 잠금 (DB)
for job in jobs (예산 초과 시 중단 → 남은 건은 lease 만료 후 재처리):
  echo   → 단계 4 처리
  inbound:
    settings 재조회 → global_enabled=false → skipped
    contact.auto_enabled=false → skipped
    paused_until > now → skipped
    now - 메시지시각 > 24h(여유 5분 빼고) → expired (대시보드 표시)
    같은 상대의 pending inbound 모두 묶어서 1회 답변 (연속 메시지에 답 1번)
    prompt = 말투 프로필 + 최근 대화 20개(messages 테이블) + 새 메시지
    Claude 응답 = "NO_REPLY" → needs_review (돈·약속·민감 주제는 봇이 답 안 하도록 지시)
    ig_send(job, text)
```
- 응답 지연: `not_before = 수신시각 + reply_delay_sec(20초)` → 연속 메시지 묶기 + 사람다운 지연
- 재시도: Claude/IG 오류 시 `status=pending`, `not_before`를 1·2·4·8분 뒤로, 5회 초과 시 `failed`
- **`ig_send()` 순서** (유일한 발송 함수):
  1. `settings.global_enabled` DB 재조회 → false면 `blocked_off` 기록 후 return
  2. `send_log` INSERT (`queue_id UNIQUE`, status=sending) → 충돌 시 이미 시도된 건 → return
  3. `POST graph.instagram.com/v24.0/me/messages` `{recipient:{id}, message:{text}}`
  4. 성공 → `ig_mid` 저장, status=sent, `messages`에 direction=bot 기록
  5. 3번 도중 프로세스가 죽으면 → 상태가 `sending`으로 남음 → **재발송하지 않고 `needs_review`** (at-most-once)

### 단계 4 — 오너 개입 감지 (echo 처리)
- echo 이벤트는 `not_before = +15초`로 적재 (봇 발송 기록이 먼저 DB에 들어갈 시간 확보)
- 판별 순서:
  1. `mid`가 `send_log.ig_mid`에 있음 → **봇이 보낸 것 → 무시** (무한루프 차단 핵심)
  2. 텍스트가 `trigger_phrases` 중 하나 포함 → `kind=intro` 작업 생성 → `ig_send(intro_message)` (전체 OFF면 차단됨, 일시정지는 무시하고 발송)
  3. 그 외 → 오너 직접 답장 → `contacts.paused_until = now + pause_minutes`, `messages`에 direction=owner 기록
- 봇은 **inbound(상대가 보낸 것)에만 답변 생성**. echo는 어떤 경우에도 Claude 답변 생성 대상이 아님 → 구조적으로 루프 불가

### 단계 5 — 대화 요약
- `daily.php`: `last_msg_at > summary_at`인 상대만 Haiku로 요약 (3~5줄, 최근 용건·약속·분위기)
- 대시보드 "요약 갱신" 버튼 → `api.php?action=summarize&igsid=` → 같은 함수 호출
- 요약문은 원문이 아닌 파생 데이터 → 평문 저장, RLS로 보호

### 단계 6 — 대시보드 (`dashboard/` → `public_html/ig/dash/`)
| 화면 | 내용 | 데이터 경로 |
|---|---|---|
| 로그인 | 이메일+비밀번호 (Supabase Auth) | supabase-js |
| 상단 | **전체 자동발송 스위치** (빨강/초록, 가장 크게) | `settings` 직접 |
| 상대 목록 | 아이디·닉네임·마지막 대화 시각·요약·토글·일시정지 남은 시간 | `contacts` 직접 |
| 주의 필요 | `expired` / `needs_review` / `failed` 건 | `api.php` (복호화) |
| 말투 프로필 | 상대별 style_guide 확인·수정, 기본 프로필 수정 | `tone_profiles` 직접 |
| 설정 | 트리거 문구, 자기소개 문구, 일시정지 시간, 응답 지연 | `settings` 직접 |
| 발송 이력 | 날짜·상대·내용·상태 | `api.php` (복호화) |

`api.php` 인증: `Authorization: Bearer <JWT>` → Supabase `/auth/v1/user` 호출로 검증 → user id가 오너 UUID일 때만 응답.

### 단계 7 — 유지 작업 (`daily.php`)
- 토큰: `token.json`의 만료까지 10일 미만 → `GET graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token` → 새 토큰·만료일 저장 (장기 토큰 60일). 실패 시 대시보드 경고 표시
- 정리: `queue` done/skipped 30일 초과 삭제, `messages` 90일 초과 삭제, `send_log`는 180일 보관 (기간은 config 상수)

## 4. 검증 계획 (`tests/run.php`)

외부 호출(IG·Claude)은 `config.php`의 `TEST_MODE`에서 가짜 응답으로 대체하고 "보낸 메시지 목록"을 기록. DB는 **별도 Supabase 테스트 프로젝트** 사용. `php tests/run.php` 한 번에 전체 실행, 항목별 PASS/FAIL 출력.

| # | 시나리오 | 통과 기준 |
|---|---|---|
| 1 | 프로필 없는 IGSID에서 inbound | Claude 프롬프트에 기본 프로필 style_guide 포함 |
| 2 | `global_enabled=false` 후 inbound 5건 + 트리거 echo 1건 + `api.php` 전 경로 호출 | 가짜 IG 발송 0건, `blocked_off`/`skipped` 기록 |
| 3 | echo 텍스트 "사실 이거 홍길동 봇이야" | intro_message 1건 발송 |
| 4 | 봇 발송 기록 없는 echo 후 inbound | `paused_until` 설정, 발송 0건 / 30분 경과 가정 후 재개 |
| 5 | 25시간 전 타임스탬프 inbound | 발송 0건, status=expired |
| 6 | 봇 발송 → 그 mid로 echo 유입 반복 10회 | 추가 발송 0건, 일시정지 안 걸림 |
| 7 | 워커 프로세스 2개 동시 실행 (`proc_open`) × inbound 20건 | 건당 정확히 1회 발송 |
| 8 | 워커가 처리 도중 강제 종료(시간예산 0.1초·`exit`) 후 재실행 | 미처리 건 전부 이후 처리됨, 유실 0, `sending` 중단 건은 needs_review |

말투 스크립트는 `analyze_tone.py --self-test`: latin-1 깨진 샘플 복원, 1년 필터, 존댓말 비율 계산 assert.

실서버 점검: 테스트 통과 후 오너 본인 부계정으로 DM → 실제 답변 확인 → 전체 OFF → 미발송 확인.

## 6. 리스크 · 확인 필요 사항

1. **Meta 앱 권한 수준** — 본인 계정 전용 앱이라도 일반 사용자 DM을 받으려면 앱을 **Live 모드**로 전환해야 하고, `instagram_business_manage_messages` 권한 수준(Standard/Advanced, 앱 검수 필요 여부)을 착수 전에 확인해야 함. 막히면 전체 일정이 멈추는 항목이라 0단계로 둠.
2. **IGSID ↔ 내보내기 상대 매칭** — 내보내기 파일엔 IGSID가 없어 username으로 매칭. 상대가 아이디를 바꿨으면 매칭 실패 → 기본 프로필 사용 (대시보드에서 수동 연결 기능 추가 가능).
3. **20개 메시지 제한** — 맥락은 봇 가동 이후 우리가 저장한 `messages`를 우선 사용, 가동 초기에만 Conversations API로 최근 20개 보충.
4. **24시간 창** — Human Agent 태그(7일)는 사람 상담원 전용 정책이라 봇 사용 불가. 초과 건은 대시보드 표시만.
5. **호스팅 사양** — cPanel의 PHP 버전, `fastcgi_finish_request` 지원 여부(PHP-FPM 여부), 크론 최소 주기를 배포 전 `phpinfo()`로 확인.
6. **비용** — Claude 호출은 답변 1건당 1회 + 요약 일 1회. 말투 분석은 상대 수만큼 1회성 호출.
