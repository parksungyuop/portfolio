## 1. 목적

README가 밝힌 대로 SparringMatch은 소개팅 앱의 매칭 인터랙션(탐색 → 제안 → 상호 수락 → 대화)을 빌린다. 그런데 v2 화면은 **비주얼만** 강했고 인터랙션은 일반 목록형 웹이었다. v3는 색·서체 토큰은 그대로 두고, 검증된 소개팅 앱의 **흐름 패턴**을 옮겨 "맞는 사람을 빨리 알아보고, 안전하게 합의하는" 경험으로 끌어올린다.

## 2. 벤치마킹 (앱 3종 + 각 웹사이트)

> 공식 사이트는 직접 확인. 인앱 세부는 제3자 UX 분석 글 기반이며, 확인하지 못한 항목(매치 화면·빈 상태·탭바 구성 등)은 근거로 쓰지 않았다. 헥스·폰트명은 공식 브랜드 문서가 아닌 2차 출처 값.

**버린 것**: 좌우 스와이프 제스처(‘좋아요 하나로 끝나는 요청’은 설계서 §3.3 위반 — 제안은 목적·강도·시간·장소를 적는 폼 유지), 사진 기반 평가, "나를 좋아한 사람" 가리기, 부스트·추천 순서 유료화, 연애 카피(§2.3). "넘기기"는 상대에게 알리지 않으며 언제든 되돌릴 수 있다.

## 4. 지킨 제약 (설계서 §5.3·§5.5·§9.2)

- 토큰·서체·라디우스 **변경 없음**. 새 요소는 기존 토큰만 사용: 공통점·안전=`--green`, 내 차례·추천 이유=`--yellow`, CTA·네온=`--red*`.
- 레드 10~15%: 카드 포스터 색은 사용자별 아바타 듀오톤(레드 아님)이라 레드 면적은 CTA·진행 바·네온 단어에 한정.
- 네온 플리커는 매칭 모달의 "성사." 한 단어, 1회. `prefers-reduced-motion`에서 전부 제거(기존 전역 규칙이 적용됨).
- 터치 타깃 44px(카드 액션·하단 탭), 모달 포커스 트랩·Esc, 상태를 색만으로 표현하지 않음(칩에 체크 아이콘+문구).
- 거리는 `약 Nkm` 버킷.

### 설계서와 달라진 점 (확정 필요)

설계서 §5.1은 하단 탭을 홈/찾기/커뮤니티/**지도**/내 정보로 두고 채팅은 헤더 배지로 뒀다. Q/A에서 모바일 대화 접근성이 가장 큰 문제였고 벤치마크 3종 모두 채팅을 탭에 두므로 **메시지를 탭으로 올리고**, 지도·이벤트·장비샵은 홈 바로가기로 내렸다. 설계서 §5.1 갱신 또는 원복 결정이 필요하다.

## 6. 검증 결과 (2026-09-21, 데스크톱·375px)

XSS 미발화 / 서지후에게 제안 201 / `data/` 403 / 저장 `aria-pressed=true` / 넘기기 −1명 + 되돌리기 버튼 / 모달 포커스 진입·Esc·포커스 복귀 / 이벤트 필터 "세미나" 1건 / "내 차례" 배지 / 수락 → 매칭 모달 / 가입 오류 시 입력값 유지, 1→2→3단계 이동 / 8개 화면 모바일 가로 넘침 없음(장비샵의 장식 아트 제외) / 콘솔 오류는 favicon 403 1건(기존, Q/A 개선 2).

## 7. 다음 단계 (이번 범위 밖)

1. 항목별 반응 제안(Hinge식): 상대의 "가능 시간"·"선호 스파링" 칩을 눌러 그 항목이 제안 폼에 미리 채워지게.
